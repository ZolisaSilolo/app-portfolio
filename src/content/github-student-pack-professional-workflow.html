Setting Up Sentry (The Real Steps)

Sentry is error tracking done right. It doesn't just log errors—it shows you exactly what the user was doing when things broke. Session replay is like having a DVR for bugs.

Why I use it: Because console.log() is not a monitoring strategy. Sentry catches errors I don't even know are happening, shows me the user's session, and groups similar errors so I can fix the root cause.

Setup time: 15 minutes.

Step 1: Sign up. Go to sentry.io, click "Sign up with GitHub", authorize it. Select the Student plan (auto-detected from your Student Pack).

Step 2: Create projects. One for frontend (React), one for backend (Python/AWS Lambda). Get your DSN keys.

Step 3: Integrate frontend. Install @sentry/react, initialize it in your app, add your DSN to environment variables. Done.

import * as Sentry from "@sentry/react";

Sentry.init({
  dsn: import.meta.env.VITE_SENTRY_DSN,
  integrations: [
    Sentry.browserTracingIntegration(),
    Sentry.replayIntegration()
  ],
  tracesSampleRate: 1.0,
  replaysOnErrorSampleRate: 1.0
});

Step 4: Integrate backend. Install sentry-sdk[aws_lambda], initialize it in your Lambda functions, store your DSN in AWS Secrets Manager (never hardcode secrets).

import sentry_sdk
from sentry_sdk.integrations.aws_lambda import AwsLambdaIntegration

sentry_sdk.init(
    dsn=os.environ.get('SENTRY_DSN'),
    integrations=[AwsLambdaIntegration()],
    traces_sample_rate=1.0
)

Step 5: Test it. Trigger an error. Check your Sentry dashboard. You should see the error, the user's session, the stack trace, and everything that led up to it.

That's it. You now have enterprise error tracking.

Setting Up Datadog (The APM Part)

Datadog is where you see what's actually happening inside your application. Not just "it's slow"—exactly which function is slow, which database query is taking too long, which API call is timing out.

Why I use it: Because "it works on my machine" is not good enough. Datadog shows me production performance, real user latency, and where bottlenecks actually are.

Setup time: 20 minutes.

Step 1: Sign up. Go to datadoghq.com, sign up with GitHub, select Student plan. Choose your region (US1 is fine).

Step 2: Get your API key. Go to Organization Settings → API Keys. Create a new key. Copy it. Store it in AWS Secrets Manager.

aws secretsmanager create-secret \
  --name datadog-api-key \
  --secret-string "your-api-key" \
  --region us-east-1

Step 3: Add the Lambda layer. Datadog provides a Lambda extension that automatically instruments your functions. Add it to your SAM template:

Globals:
  Function:
    Layers:
      - !Sub "arn:aws:lambda:${AWS::Region}:464622532012:layer:Datadog-Python312:95"
    Environment:
      Variables:
        DD_API_KEY_SECRET_ARN: !Sub "arn:aws:secretsmanager:..."
        DD_SITE: "datadoghq.com"
        DD_SERVICE: "portfolio-api"
        DD_TRACE_ENABLED: "true"

Step 4: Deploy and verify. Deploy your Lambda functions. Wait 2-3 minutes. Go to Datadog APM. You should see your service, traces, and metrics.

Step 5: Add custom metrics. Track business metrics, not just technical ones:

from datadog_lambda.metric import lambda_metric

lambda_metric(
    'portfolio.chat.messages',
    1,
    tags=['user_type:authenticated']
)

Now you have full APM tracing and custom metrics. For free.

Setting Up GitHub Actions (The CI/CD Part)

GitHub Actions is CI/CD built into GitHub. Every push triggers a workflow. Tests run automatically. Builds happen automatically. Deployments happen automatically.

Why I use it: Because manual deployments are error-prone and waste time. Automated deployments are consistent and fast.

Setup time: 30 minutes.

Create .github/workflows/deploy.yml:

name: Deploy Portfolio

on:
  push:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '18'
      - run: npm ci
      - run: npm test
      - run: npm run build

  deploy:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          aws-access-key-id: ${secrets.AWS_ACCESS_KEY_ID}
          aws-secret-access-key: ${secrets.AWS_SECRET_ACCESS_KEY}
          aws-region: us-east-1
      - run: aws s3 sync dist/ s3://your-bucket/ --delete

Add your AWS credentials to GitHub Secrets. Push to main. Watch it deploy automatically.

3,000 minutes per month means you can run this on every commit without worrying about limits.
