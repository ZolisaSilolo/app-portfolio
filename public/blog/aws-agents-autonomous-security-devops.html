What Are AWS Agents, Actually?

Think of them as AI-powered teammates that never sleep. AWS launched two in 2026:

AWS Security Agent is like having a penetration tester on staff. It doesn't just scan for known vulnerabilities—it actually tries to break into your application. It reads your code from GitHub, understands your architecture, and tests real attack scenarios. When it finds something, it generates a pull request with the fix.

AWS DevOps Agent is your ops engineer. It watches CloudWatch metrics, reads logs, correlates events, and investigates issues automatically. When something breaks at 3 AM, it's already figured out the root cause by the time you wake up.

Both agents have a 2-month free trial. I'm using that to prove they're worth it.

My Architecture (The Actual Setup)

My portfolio is a pretty standard serverless stack:

Frontend: React + TypeScript hosted on S3 with CloudFront. Nothing fancy, but it's fast and cheap.

Backend: Four Lambda functions in Python 3.12. One handles the AI chatbot (using Cohere), one serves portfolio data, one manages admin uploads, and one tracks sessions. All behind API Gateway with Cognito authentication.

Data: DynamoDB for sessions and analytics. S3 for content storage. Secrets Manager for API keys (because hardcoding secrets is for people who hate themselves).

The agents plug into this stack and just... work. Security Agent scans everything. DevOps Agent monitors everything. Both talk to GitHub and Slack to keep me informed.

Setting Up Security Agent (The Real Steps)

I'm not going to lie—the setup took me about 2 hours. But most of that was waiting for DNS propagation. Here's what actually matters:

Step 1: Create an agent space. This is basically a container for all your security testing. One command in the AWS CLI:

aws securityagent create-agent-space \
  --name "ZolisaPortfolioSecurityAgent" \
  --region us-east-1

Step 2: Verify your domain. AWS needs to know you actually own the site you're testing. Add a TXT record to your DNS. Wait 15 minutes. Verify. Done.

Step 3: Connect GitHub. This is where it gets cool. The agent reads your actual code to understand what it's testing. OAuth flow through the console, grant repo access, and you're set.

Step 4: Create IAM roles. The agent needs permissions to write logs, read secrets, and create network interfaces. Standard AWS security stuff.

Step 5: Run your first test. Point it at your site, tell it to use automatic remediation, and let it run. Mine took 8.2 hours.

What It Found (The Uncomfortable Truth)

The agent found 12 vulnerabilities in my "secure" portfolio site. Three were critical:

Weak Cognito password policy. I had it set to accept 8-character passwords with no complexity requirements. The agent tested brute force attacks and showed me exactly how fast it could crack them. It generated a CloudFormation update to require 12+ characters with complexity. I merged the PR.

Hardcoded admin password in the client bundle. Yeah. I had an admin password in an environment variable that got bundled into the React app. Anyone could read it. The agent found it, showed me the security risk, and generated a PR to move authentication to Cognito. Embarrassing, but fixed.

Using SSM Parameter Store instead of Secrets Manager. My Lambda functions were pulling API keys from Parameter Store, which doesn't have automatic rotation. The agent explained why this was risky and generated code to migrate to Secrets Manager. Done.

It also found CORS wildcards, missing Lambda encryption, and no WAF protection. All fixed with auto-generated PRs.

Setting Up DevOps Agent (Even Easier)

The DevOps Agent setup was simpler because it just watches what's already there:

Create agent space. Same as Security Agent.
Create IAM roles. Read-only access to CloudWatch, logs, Lambda, API Gateway, DynamoDB.
Connect services. Link your AWS account, GitHub repo, and Slack workspace.
Configure metrics. Tell it what to watch (Lambda errors, API latency, DynamoDB throttles).

That's it. It starts monitoring immediately.

What It Does (The Cool Part)

Last week, my chatbot Lambda started throwing errors. The DevOps Agent:

  1. Detected the error spike in 45 seconds
  2. Analyzed the logs and found "CohereAPIError: Rate limit exceeded"
  3. Traced it to a single IP address (me, testing)
  4. Identified the root cause: no per-user rate limiting
  5. Suggested a fix: implement rate limiting and request queuing
  6. Posted everything to Slack

Total time from error to diagnosis: 2 minutes. Without the agent, I would have found out when users complained, spent 30 minutes digging through logs, and another hour figuring out the cause.

Adding Monitoring (Because Why Not)

While I was at it, I added Sentry and Datadog using my GitHub Student Pack (both free):

Sentry tracks frontend and backend errors. Session replay shows me exactly what users experienced when something broke. It's like having a DVR for bugs.

Datadog gives me APM tracing across all my Lambda functions. I can see exactly where time is spent, which functions are slow, and where bottlenecks are forming.

Both integrate with the DevOps Agent, so it can correlate errors in Sentry with metrics in Datadog and logs in CloudWatch. It's like having a detective that actually knows what it's doing.
